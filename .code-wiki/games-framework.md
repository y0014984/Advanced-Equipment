# Games Framework

## overview

`addons/games` adds eight turn-based games played between AE3 computers on the same in-game network, one seat per device: chess, checkers, rock paper scissors and battleship (2 seats), ludo and snakes and ladders (4), uno and blackjack (8). Two front ends - a web desktop app and a terminal command - share one server-authoritative match.

## current behavior

- **The server owns every match.** `AE3_games_tables` is a server-only `missionNamespace` HashMap, `tableId -> table`, never broadcast and never sent whole to a client. Every mutating function opens with `if (!isServer) exitWith {[...] call CBA_fnc_serverEvent}`; events are `ae3_games_host/join/start/leave/close/move/list/open/install/roster/setOverride`.
- **A seat belongs to the device, not the player** (`[deviceNetId, seatIndex, label]` in `table >> seats`; `label` is blank except on a practice seat). That is what makes a match resumable: closing the app, releasing the mutex, powering the laptop off, dying or disconnecting all leave the seat alone. Only an explicit leave, a host close, a deleted device or `AbandonTimeout` removes one. `fnc_getTables` answers a device with `resumable` and `joinable` lists, which is the lobby's Continue/Join split. A device may hold more than one seat (practice seats, below), so `fnc_seatsOf` returns all of them and `fnc_seatOf` returns the one it is playing - `table >> active` (`deviceNetId -> seat`, written by `fnc_setActiveSeat`), falling back to the lowest it holds. `fnc_pushState` therefore sends **one message per device**, not per seat.
- **Rules contract**, one file per game, `fnc_rules_<game>.sqf`, server only: `["new", _seatCount] -> _state`, `["turn", _state] -> seat or -1 for any`, `["apply", _state, _seat, _move] -> [_ok, _newState, _reasonKey]`, `["view", _state, _seat] -> seat view`, `["winner", _state] -> -1 running / seat / -2 draw`, `["timeout", _state] -> [_ok, _newState]`. `fnc_gameInfo` is the registry (rules function, min and max seats, title); adding a game means a rules file, a row there, a `CfgGames` class, a `fnc_tui_<game>` wrapper, a renderer branch in `fnc_tui_renderBoard` and in `ae3games.js`, and a row in `fnc_registerApps`.
- **`view` is why rules are server side.** Uno hands, the blackjack hole card and shoe, a battleship fleet and an unrevealed rock paper scissors throw are stripped per seat before anything leaves the server, so a modified client has nothing to read. All randomness (shuffles, deals, dice) happens in the rules function.
- **A seat's own name** is the fourth `fnc_setTableOption` answer (`seatname`) and the only one that is still taken after the phase leaves `lobby`, because nothing about the game is decided by it: it writes element 2 of the seat row, capped at 24 characters, empty meaning the device's own name. `fnc_pushState` already falls back to `fnc_deviceLabel` for a blank label and `fnc_startTable` carries element 2 through the renumber, so both front ends and the Zeus roster print it with no further work. Reached from the web lobby and from under the board (`seatNameButton`), and from the terminal as `seatname`/`me`.
- **The lobby settles three things before `fnc_startTable` builds a board**, all through `fnc_setTableOption` on the server and all meaningless once the phase leaves `lobby`: the table's `name` (host, shown in every other device's lobby instead of the game title), a seat's side `pref` (`white`/`black`/`random`, kept in `table >> prefs` keyed by `str seat`) and the host's chosen `starter` seat. `fnc_gameInfo`'s fifth element says which of those a game asks for - `"colour"` (chess), `"starter"` (everything but rps) or `"none"`. `fnc_startTable` turns the answers into a seat **order** and renumbers from zero, because every rules function builds its board for seat 0 first: a colour game slots white into 0 and black into 1 and shuffles whoever asked for random, refusing with `SideTaken` when two seats want the same side; a starter game rotates the list until the chosen seat is at the front. The refusal has to be carried out of the `switch` in a flag - an `exitWith` inside a `case` block leaves the case, not the function.
- **Practice seats** (`fnc_addDummySeat`, host only, lobby only, gated on the `DebugSeats` setting which is off by default): the hosting device takes another seat at its own table and switches between them with `fnc_setActiveSeat`, so one laptop can play every side while a mission is built. Seats are ordinary in every other respect, including `view` stripping - the switch is what reveals the other hand, not the network.
- **Move validation** (`fnc_applyMove`): the seat belongs to the sending device, the sending machine is the device's `computer_getLocality`, the device is powered on, its `AE3_computer_mutex` holder is alive, the route to the host device still resolves, the phase is `play`, and the rules accept the move. A refusal changes nothing and goes only to the player who tried it, as a stringtable key.
- **Never decide "is anyone using this device" from `computer_getLocality`.** It returns `2` both for an unused device and for a device whose operator is on the server machine, which is every player in a hosted or local multiplayer game - treating `2` as nobody left every host player's request unanswered and the whole UI dead. `fnc_operatorOwner` is the test: the `AE3_computer_mutex` holder must exist, be a man and be alive, and its `owner` is the machine to answer, `2` included. `pushState`, `pushNotice`, `getTables` and `applyMove` all go through it.
- **Cost**: no polling, no broadcast variable, no per-frame work. One `CBA_fnc_serverEvent` in, one `CBA_fnc_ownerEvent` per *seated* device out, each a JSON string; a seat whose device nobody is using is skipped, not queued. `fnc_manageSweep` registers the 10 s `fnc_tableSweep` handler only while a table exists and removes it with the last one. Rendering never calls SQF.
- **Power**: `fnc_applyGamePowerLoad` adds the draw to `AE3_power_powerConsumption` - the figure the device's own turn-on and standby wrappers hand to `AE3_power_fnc_updateSelfPower` - so it survives power cycling, drains an internal battery through the normal battery calculation and counts towards a provider's capacity. The base value is stored once in `AE3_games_baseConsumption` and restored exactly when the load drops to zero. Full draw while a game is open, `IdleDraw` (default 0) while a seat is parked.
- **Settings**: `fnc_getSetting [_device, _name]` resolves device object variable (`AE3_games_set_<name>`, written by the `AE3_Module_Games` module or a Zeus asset panel) -> curator session override (`AE3_games_overrides`) -> CBA setting `AE3_Games_<name>`. `fnc_setSetting` is the only writer. `fnc_refreshAvailability` publishes the resolved Enabled flag as `AE3_games_enabled`, which the desktop app list filters on through `requiresVar`.
- **Every game draws twice.** `ae3games.js` carries a board renderer (coloured chess board with outlined glyphs, ludo cross on a 15x15 grid, printed snakes and ladders board, uno and blackjack cards, rock paper scissors hands, two charted battleship grids) and the plain list the terminal shows. Which one runs is the `graphical` flag on the view, resolved from the `GraphicalUI` setting on the server - the JS never decides. The ludo ring (52 cells), home columns and yards are coordinate tables in the JS; the snakes and ladders jump table is **sent with the view** so the board drawn is the board the rules use.
- **Battleship has a setup phase.** State is `[_fleets, _shots, _side, _lastKey, _result, _ready]` with a fleet as `[length, cell indices]` per ship, so a ship can be sunk, counted and drawn as an object rather than guessed from a grid string. `turn` returns -1 until both seats are `ready`, which is what lets both lay out at once; the setup moves are `place <ship> <square> <h|v>`, `random`, `clear` and `ready`. The view carries the phase, the own fleet, both afloat counts and the ready flags.
- **Rock paper scissors reveals.** The state carries `_lastThrows` and `_lastWinner` past the round that produced them, so both throws and the verdict can be shown; the open round is still stripped to "the other seat has thrown".
- **Web front end**: one bundle, `ui/web/js/ae3games.js`, registered as eight `script`-kind ext apps sharing `scriptPath` and `factory = "AE3_makeGameApp"`, told apart by `extra.gameId`. The browser talks back through `AE3_desktop_fnc_registerCmd` commands (`games_list/host/join/start/leave/move/open/option/seat/dummy`), so `fnc_jsRouter` is untouched. `A3.on` has no unsubscribe, so one module-level listener fans out to a `sinks` array each open window adds itself to and removes itself from on close.
- **Terminal front end**: `CfgGames` classes (`/games/<name>`, `sshCompatible = 0`) -> `fnc_tui_<game>` -> `fnc_tui_session`, which prints with `shell_stdout`, reads with `shell_stdin`, and registers an `ae3_games_viewUpdated` handler so an opponent's move prints while the prompt is waiting. Installed per computer by `fnc_installGames` through `AE3_armaos_fnc_link_init`, gated on `AE3_cap_hasTerminal`.
- **Installation is the default, not a choice.** The server subscribes to `ae3_armaos_deviceReady` (raised by `fnc_device_initComplete` once the terminal, the filesystem and the capability flags all exist) and installs every id from `fnc_gameIds` on any device whose `Enabled` setting is on, removing every id when it is off. `fnc_computer_initWithCommands` already links **all** of `CfgGames` for a computer built with games, and `fnc_link_add` throws on a name it already holds, so `fnc_installGames` asks only for the ids missing from `AE3_Links`; without that filter the unhandled throw fires inside CBA's wait loop and leaves it erroring every frame. That event is the right hook and `InitPost` is not: `fnc_installGames` waits on `AE3_cap_hasTerminal` and a device that never gets one - a generator, a battery - would leave a `CBA_fnc_waitUntilAndExecute` spinning forever.
- **`AE3_AddGames` narrows that set** (Eden + Zeus, `category = "AE3_armaosModules"`): a checkbox per game, all defaulting to **true**, and `fnc_module_addGames` applies the whole list in one pass - ticked ids to `FUNC(installGames)`, the rest to `FUNC(removeGames)` - so a module dropped and left alone changes nothing. The Eden path reads the checkbox values off the module logic by property name on the server and applies to `_syncedUnits`; the curator path runs on the curator's machine only, resolves the computer with `AE3_main_fnc_zeus_checkForComputer` (`BIS_fnc_curatorObjectPlaced_mouseOver`; module position is not at the drop target), guarded by `AE3_games_zeusHandled` because an `isGlobal = 1` curator module runs twice on the curator client (own init + server `BIS_fnc_MP`), and asks with a ZEN dialog or leaves the full set alone when ZEN is absent.
- **`fnc_removeGames`** drops the `AE3_Links` entry (which is what `fnc_shell_process` resolves a command name through) and `delObj`s the file under `/games`, then broadcasts both. There is no per-laptop games attribute of any kind left: the old `AE3_Game_Snake` checkbox and `AE3_armaos_fnc_attr_addGames` are gone, since a computer has every game to begin with.
- **`AE3_Module_Games` is the only settings surface** (Eden + Zeus, `category = "AE3_mainModules"`, `scope = 2`): `fnc_module_games` splits on `BIS_fnc_moduleInit_isCuratorPlaced`. The Eden half runs on the server, reads one `AE3_Module_Games_<setting>` property per setting off the module logic and writes each through `FUNC(setSetting)` onto `_syncedUnits`, or onto `objNull` (mission wide) when nothing AE3 is synced to it; `"default"` and a blank edit box write nothing, so the mission setting keeps control. The four bool settings are **Combos** (`default`/`yes`/`no`), not Checkboxes: a checkbox is always on or off, so it would write a value onto every synced computer and leave no way of saying "whatever the mission setting says".
- **Zeus**: the curator half of `fnc_module_games` (`category = "AE3_mainModules"`, listed in `CfgPatches >> units[]`) -> `fnc_zeus_games` on the curator's machine -> `fnc_getRoster` on the server, which refuses anyone without a curator logic -> `fnc_zeus_showRoster`, a ZEN dialog for the session settings and closing a table, falling back to a systemChat roster when ZEN is absent.

## decisions

- Rules on the server rather than in JS: it is the only way to keep hidden information hidden and the only way two front ends can share one match without a second implementation.
- A seat keyed by device rather than by player, so resuming needs no identity tracking and matches the brief of one seat per computer.
- Joining is only possible while a table is in its `lobby` phase, and `fnc_startTable` builds the state for the number of seats that actually sat down. A game for up to eight seats cannot be dealt before that number is known.
- The games draw is layered onto `AE3_power_powerConsumption` instead of a private drain loop, so it obeys every existing power rule for free.

## gotchas

- `AE3_games_tables` holds HashMaps: they must never be put on a CBA event or a public variable. Everything leaving the server goes through `CBA_fnc_encodeJSON` and is decoded in `XEH_postInit.sqf` with mode 2.
- **Every string in a view may be a stringtable key**, not only `textKey`: titles, table names and status lines all travel as `$STR_...` because a dedicated server may run another language. `XEH_postInit.sqf` walks the decoded payload recursively and localizes any string starting with `$STR`, so a key added anywhere in a payload is handled without touching the front ends. Leaving that to the front end is what put raw `$STR_AE3_Games_Title_Chess` in the lobby.
- ESC is swallowed by the desktop (`fnc_desktop_openWeb.sqf`), so no game may use it. **No file under `ui/web/js` may contain a non-ASCII byte**: `extapps.js` pulls the bundle in with `A3API.RequestFile` and injects it as `node.text`, and the engine hands that text back decoded a byte at a time, so a UTF-8 chess glyph arrives as three Latin-1 characters - the mojibake widened every square past its grid track and pushed the eighth file off the board. Write them as `\uXXXX` escapes (or HTML entities in an `innerHTML` string); `grep -P "[^\ux00-\ux7F]"` over the directory must come back empty. Separately from the encoding: the laptop browser never falls back to the emoji font, so **no codepoint that needs it may carry meaning** - U+1F0CF (the uno app icon), U+26AB, U+270A..C and U+2693 all drew as empty boxes. BMP symbol blocks only (geometric shapes, card suits, dice, arrows), and where legibility decides a game - a checkers king, an uno action card, an rps throw - draw it in CSS or write the word instead.
- `fnc_tui_session` suspends (`shell_stdin`), so it only runs from a command's scheduled context, and it keeps its per-session state in `uiNamespace` because a CBA event handler cannot capture locals.
- Only English and Original exist in `addons/games/stringtable.xml`; the other AE3 components carry six more languages.
- A laptop carries **no** games attributes: the five that lived in `armaos/CfgVehicles.hpp`'s `AE3_LAPTOP_SOFTWARE_ATTRIBUTES` macro are gone, and `AE3_Module_Games` is where those settings are set. Do not move them back in from this component by re-opening the laptop classes: that resets those classes' base and takes the laptops out of Eden and Zeus entirely - see [[eden-zeus-tooling]].
- **Module config**: `games/CfgVehicles.hpp` declares `Module_F: Logic { class AttributesBase { Checkbox; Combo; Edit; }; }` like the other components. Never forward-declare `AttributesBase` directly under `CfgVehicles` - it creates a stub vehicle class and the startup error `No entry ...CfgVehicles/AttributesBase.scope`. Do not re-declare the controls inside `Attributes` (L-C14 unused external).

## re-verify when

- A game is added, or the rules contract or `fnc_gameInfo` changes.
- `AE3_desktop_fnc_registerCmd`, `registerExtApp`, `routeReply` or the `jsSend`/`AE3_recv` bridge changes shape.
- The power model changes where a consumer's draw is read from.
